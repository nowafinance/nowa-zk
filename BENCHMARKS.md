# Proof Generation Benchmarks

## Results (2026-09-01)

Measured against the circuit as it stands today — `BatchSize = 25`
(`prover/circuits/state_circuit.go`), with genuine per-op EdDSA (Maker-leg)
signature verification and genesis-safe Merkle folding in-circuit. These numbers
supersede everything below the 2025-12-01 table further down, which was measured
against a `BatchSize = 128` circuit from an earlier, since-fixed version that did not
correctly verify signatures — not a valid comparison point for current throughput.

### Summary
| Batch Size | Time per Batch (Prove) | Time per Tx | Throughput |
|------------|------------------------|-------------|------------|
| 25 tx      | ~36.40 s               | ~1.456 s    | ~0.69 tx/s |

### Detailed Phase Breakdown (25 tx, full batch)
| Phase | Time | Description |
|-------|------|--------------|
| **Compile** | ~38.7 s | `frontend.Compile` — one-time per circuit version, not per batch. |
| **Setup** | not re-measured this run | One-time Groth16 trusted setup (`make setup`); regenerating `state.{ccs,pk,vk}` in this dev sandbox competes with other running processes for memory, so wall time wasn't independently re-benchmarked here — see Methodology below. |
| **Witness** | ~5.71 ms | Building the witness for all 25 ops from transition inputs. |
| **Prove** | ~36.40 s | Groth16 proof generation (`groth16.Prove`) for a full 25-op batch, real EdDSA-signed transfers. |
| **Verify** | ~2.52 ms | Off-chain proof verification (`groth16.Verify`). |

**Total Proving Time (Witness + Prove):** ~36.40 s (~1.456 s/tx)

## Why this is much slower per-tx than the old numbers

The 2025-12-01 numbers below (`~15.5 ms/tx`) came from a circuit that, at the time,
did not actually verify Maker/Taker EdDSA signatures per operation — that gap was one
of the correctness bugs fixed this session (see git history:
`fix: deposit-signing circuit bug and account-onboarding bug`, and the genesis/MiMC
fixes in `feat/batch-scaling-genesis-and-da-fixes`). Real in-circuit EdDSA
verification plus genesis-safe Merkle folding meaningfully raises the constraint
count per operation — the number above is the honest cost of that correctness, not a
regression to fix.

## Methodology
- **Hardware**: 12th Gen Intel(R) Core(TM) i7-12700H.
- **Circuit/keys**: real `~/.nowa-zk/keys/state.{ccs,pk,vk}` as generated by
  `make setup` against the current circuit (4,645,668 constraints, `BatchSize=25`),
  not a synthetic/reduced fixture.
- **Witness**: 25 sequential real transfers between two accounts, each with a genuine
  EdDSA signature (mirrors `TestStateTransitionCircuit_FullBatchOf25`) — the same
  shape a real Sequencer batch produces.
- **Command**:
  ```bash
  cd prover && go test -bench=BenchmarkStateTransitionCircuit -benchtime=1x -run=^$ -v ./circuits/
  ```
  (`prover/circuits/benchmark_test.go`)
- `-benchtime=1x` runs a single iteration — proving a 4.6M-constraint circuit is
  expensive enough that `go test -bench`'s default multi-iteration timing isn't
  practical on a dev machine; treat the numbers above as one real, representative
  sample rather than an average over many runs.
