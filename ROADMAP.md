# ZK-Sequencer - Project Roadmap

## Project Overview

Building a **ZK-Sequencer** that generates ZK proofs for the **Tan-ZK L1 Network** and submits them back to the same chain.

**Repository**: https://github.com/tannetwork/zk-sequencer (this repo)  
**Tan-ZK Network**: https://github.com/tannetwork/tan-zk (separate L1 chain)  
**Target**: v1.0.0 Release in 8 weeks  
**Architecture**: Standalone, centralized sequencer and verifier for Tan-ZK (phase 1). We will decentralize both components in future phases.

---

## 🎯 Project Scope

### What We're Building

**ZK-Sequencer Architecture:**
```
Tan-ZK L1 Chain (runs independently)
    ↑ reads txs          ↓ submits proofs
    |                    |
ZK-Sequencer Service (this repo)
    ├── Sequencer (Go) - batches transactions
    ├── Prover (Go + Gnark) - generates ZK proofs
    └── Contracts (Solidity) - verifies proofs on Tan-ZK
```

### Key Components (This Repo)

**What's in zk-sequencer repo:**
- ✅ **Sequencer Service** (Go): Watches Tan-ZK, batches transactions
- ✅ **Prover Service** (Go + Gnark): Generates ZK proofs
- ✅ **Smart Contracts** (Solidity): Deployed on Tan-ZK for proof verification
- ✅ **API Layer**: REST APIs for monitoring and status
- ✅ **Docker Setup**: Containerized deployment

**What's NOT in this repo:**
- ❌ Tan-ZK blockchain itself (that's in tan-zk repo)
- ❌ Consensus modifications
- ❌ Cosmos SDK modules

### Technology Stack

**Sequencer Service**
- **Language**: Go 1.21+
- **Framework**: Custom service (no Cosmos SDK dependency)
- **RPC Client**: Connect to Tan-ZK via JSON-RPC/WebSocket
- **Storage**: LevelDB/BadgerDB for local state

**Prover Service**
- **Language**: Go (using Gnark)
- **ZK Framework**: Gnark (Groth16/PLONK)
- **Output**: Generates Solidity verifier contracts
- **Alternative Future**: Plonky3 (Rust, when production-ready)

**Smart Contracts**
- **Language**: Solidity 0.8.20+
- **Framework**: Hardhat
- **Deployment Target**: Tan-ZK EVM layer
- **Verifier**: Auto-generated by Gnark

```go
package batcher

type BatchBuilder struct {
    txPool       *txpool.TxPool
    stateManager *state.StateManager
    batchSize    int
    batchNumber  uint64
}

func NewBatchBuilder(
    txPool *txpool.TxPool,
    stateManager *state.StateManager,
    batchSize int,
) *BatchBuilder

// Build next batch
func (bb *BatchBuilder) BuildBatch() (*Batch, error) {
    // 1. Get transactions from pool
    txs := bb.txPool.GetTransactions(bb.batchSize)
    
    // 2. Get old state root
    oldRoot := bb.stateManager.GetStateRoot()
    
    // 3. Execute transactions (simulate)
    newRoot, traces := bb.executeTransactions(txs)
    
    // 4. Create batch
    batch := &Batch{
        Number:       bb.batchNumber,
        Transactions: txs,
        OldStateRoot: oldRoot,
        NewStateRoot: newRoot,
        Traces:       traces,
        Timestamp:    time.Now().Unix(),
    }
    
    bb.batchNumber++
    return batch, nil
}

// Execute transactions and generate traces
func (bb *BatchBuilder) executeTransactions(txs []*Transaction) 
    (common.Hash, []*ExecutionTrace, error)
```

```go
// sequencer/cmd/sequencer/main.go
package main

type SequencerService struct {
    tanClient    *tanrpc.TanZKClient
    txPool       *txpool.TxPool
    batchBuilder *batcher.BatchBuilder
    stateManager *state.StateManager
    proverClient *ProverClient
    
    // Channels
    blockChan    chan *types.Block
    batchChan    chan *Batch
    proofChan    chan *Proof
    stopChan     chan struct{}
}

func (s *SequencerService) Start() error {
    // 1. Connect to Tan-ZK
    // 2. Subscribe to blocks
    // 3. Start batch builder
    // 4. Start proof submitter
    go s.blockProcessor()
    go s.batchProcessor()
    go s.proofProcessor()
}

func (s *SequencerService) blockProcessor() {
    for {
        select {
        case block := <-s.blockChan:
            // Add block transactions to pool
            s.processBlock(block)
        case <-s.stopChan:
            return
        }
    }
}

func (s *SequencerService) batchProcessor() {
    ticker := time.NewTicker(10 * time.Second)
    for {
        select {
        case <-ticker.C:
            // Build batch every 10 seconds
            batch, err := s.batchBuilder.BuildBatch()
            if err != nil {
                continue
            }
            // Send to prover
            s.requestProof(batch)
        case <-s.stopChan:
            return
        }
    }
}

func (s *SequencerService) proofProcessor() {
    for {
        select {
        case proof := <-s.proofChan:
            // Submit proof to Tan-ZK
            s.submitProof(proof)
        case <-s.stopChan:
            return
        }
    }
}
```

```go
// prover/circuits/batch.go
package circuits

const BATCH_SIZE = 100 // Start with 100, scale to 1000

type BatchCircuit struct {
    // Public inputs
    OldStateRoot frontend.Variable `gnark:",public"`
    NewStateRoot frontend.Variable `gnark:",public"`
    BatchNumber  frontend.Variable `gnark:",public"`
    
    // Private witnesses (array of transactions)
    Transactions [BATCH_SIZE]TransactionCircuit
    
    // Intermediate state roots (after each tx)
    IntermediateRoots [BATCH_SIZE]frontend.Variable
}

func (circuit *BatchCircuit) Define(api frontend.API) error {
    currentRoot := circuit.OldStateRoot
    
    // Process each transaction
    for i := 0; i < BATCH_SIZE; i++ {
        tx := circuit.Transactions[i]
        
        // Verify transaction with current state root
        tx.OldStateRoot = currentRoot
        
        // Define transaction constraints
        err := tx.Define(api)
        if err != nil {
            return err
        }
        
        // Update current root
        currentRoot = tx.NewStateRoot
        circuit.IntermediateRoots[i] = currentRoot
    }
    
    // Final state root must match
    api.AssertIsEqual(currentRoot, circuit.NewStateRoot)
    
    return nil
}
```

```go
// prover/cmd/prover/main.go
package main

import (
    "github.com/gin-gonic/gin"
    "github.com/consensys/gnark/backend/groth16"
)

type ProverService struct {
    circuit      *circuits.BatchCircuit
    provingKey   groth16.ProvingKey
    verifyingKey groth16.VerifyingKey
    
    // Proof queue
    queue   chan *ProofRequest
    workers int
    
    // Store proof results
    proofs map[string]*ProofResult
    mu     sync.RWMutex
}

func NewProverService(workers int) (*ProverService, error) {
    // 1. Load or generate circuit keys
    pk, vk, err := loadOrGenerateKeys()
    if err != nil {
        return nil, err
    }
    
    ps := &ProverService{
        provingKey:   pk,
        verifyingKey: vk,
        queue:        make(chan *ProofRequest, 100),
        workers:      workers,
        proofs:       make(map[string]*ProofResult),
    }
    
    // Start worker pool
    for i := 0; i < workers; i++ {
        go ps.worker()
    }
    
    return ps, nil
}

func (ps *ProverService) worker() {
    for req := range ps.queue {
        proof, err := ps.generateProof(req)
        ps.storeResult(req.ID, proof, err)
    }
}

func (ps *ProverService) generateProof(req *ProofRequest) (*Proof, error) {
    // 1. Convert execution trace to circuit witness
    witness, err := traceToWitness(req.Trace)
    if err != nil {
        return nil, err
    }
    
    // 2. Generate proof using Gnark
    proof, err := groth16.Prove(ps.circuit, ps.provingKey, witness)
    if err != nil {
        return nil, err
    }
    
    // 3. Serialize for Solidity
    return serializeProof(proof), nil
}

// API handler
func (ps *ProverService) handleProve(c *gin.Context) {
    var req ProofRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }
    
    // Generate unique ID
    req.ID = generateID()
    
    // Add to queue
    ps.queue <- &req
    
    c.JSON(202, gin.H{"request_id": req.ID})
}
```

```go
// Batch ECDSA verification
func (circuit *BatchCircuit) verifySignaturesBatch(api frontend.API) error {
    // Gnark's optimized batch ECDSA verification
    // Verify multiple signatures together (much faster)
    signatures := make([]ecdsa.Signature, BATCH_SIZE)
    for i := 0; i < BATCH_SIZE; i++ {
        signatures[i] = circuit.Transactions[i].Signature
    }
    return ecdsa.BatchVerify(api, signatures)
}

// Merkle proof optimization
func (circuit *BatchCircuit) optimizeMerkleProofs(api frontend.API) {
    // Cache intermediate Merkle tree nodes
    // Reuse computations for overlapping paths
    nodeCache := make(map[int]frontend.Variable)
    
    for i := 0; i < BATCH_SIZE; i++ {
        proof := circuit.Transactions[i].MerkleProof
        // Reuse cached nodes when paths overlap
        verifyWithCache(api, proof, nodeCache)
    }
}

// Parallel constraint generation
func (circuit *BatchCircuit) parallelDefine(api frontend.API) error {
    // Split circuit into chunks
    chunkSize := 100
    for chunk := 0; chunk < BATCH_SIZE/chunkSize; chunk++ {
        start := chunk * chunkSize
        end := start + chunkSize
        
        // Define constraints for this chunk
        for i := start; i < end; i++ {
            circuit.Transactions[i].Define(api)
        }
    }
    return nil
}
```

### Alternative Path 3: Recursive Proofs for Massive Batches

**Status**: Optional enhancement for v2.0.0

**Concept**: Use proof recursion to scale beyond 1000 transactions per batch.

**How It Works:**
```
Prove 1000 txs → Proof_1 (10 min)
Prove 1000 txs → Proof_2 (10 min)
Prove 1000 txs → Proof_3 (10 min)
    ↓
Prove "Proof_1 AND Proof_2 AND Proof_3 are all valid"
    ↓
Single Recursive Proof (2 min)
    ↓
Submit to Tan-ZK (constant gas cost)
```

**Advantages:**
- Scale to 10,000+ transactions per batch
- Constant verification cost on-chain
- Amortize proving cost over more transactions
- Lower per-transaction cost

**Challenges:**
- More complex circuit design
- Requires recursive SNARK composition
- Longer total proving time (but parallelizable)
- More complex error handling

### Glossary

**ZK Terms:**
- **ZK-SNARK**: Zero-Knowledge Succinct Non-Interactive Argument of Knowledge
- **Groth16**: Fast ZK-SNARK with trusted setup
- **PLONK**: Universal ZK-SNARK (no per-circuit setup)
- **Circuit**: Mathematical representation of computation to prove
- **Witness**: Private inputs to the circuit
- **Proof**: Cryptographic proof of correct computation
- **Verifier**: Contract/code that verifies proofs

**Sequencer Terms:**
- **Batch**: Group of transactions processed together
- **State Root**: Merkle root representing account states
- **Execution Trace**: Record of state changes from transactions
- **Merkle Proof**: Proof of inclusion in Merkle tree

**Blockchain Terms:**
- **L1**: Layer 1 blockchain (Tan-ZK in this case)
- **EVM**: Ethereum Virtual Machine
- **Cosmos SDK**: Framework for building blockchains
- **Ethermint**: EVM implementation for Cosmos chains
